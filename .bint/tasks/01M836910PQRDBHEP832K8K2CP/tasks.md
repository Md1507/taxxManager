# Công việc Bước 2.3

- [x] TSK-1 [AC-3]: Ghi baseline task-only, HEAD/index và checksum bốn migration/designer cũ trước sửa — xong khi: baseline bao gồm S21/S22 chưa commit, verify.command trống và mọi tệp dự kiến nằm allow; không truy cập DB người dùng.
- [x] TSK-2 [AC-1]: Thêm Protection feature dùng BCL AesGcm, external durable key ring, envelope/AAD và fail-closed errors — xong khi: không auto-create key vận hành, context ràng buộc database/profile/entity/PK/field; key lỗi/ciphertext lỗi không fallback hoặc log secret.
- [x] TSK-3 [AC-1]: Chuyển names và ba khoản tiền sang encrypted storage, hydrate và sensitive dirty detection trong Data — xong khi: fresh context đọc đúng null/empty/Unicode/decimal, update public values được lưu; thiếu/hỏng payload không trả default và model không map plaintext columns.
- [x] TSK-4 [AC-2]: Tích hợp audit collector/save coordinator cùng TaxRules transaction guards — xong khi: sync/async/mixed batch tạo đúng events có encrypted actor/context/before-after/UTC; no-op không event; caller transactions/savepoints/cancellation/Save(false)/retry semantics theo plan, không audit độc lập sau commit.
- [x] TSK-5 [AC-2]: Enforce append-only và normal deletion/purge qua API riêng — xong khi: caller tracked mutation audit bị chặn; cascade chưa load vẫn có delete events atomic, ordinary-delete giữ audit, purge xóa mọi audit/graph target và giữ nguyên profile khác.
- [x] TSK-6 [AC-3]: Thêm migration/designer/snapshot mới cùng legacy reader và explicit synthetic copy-forward upgrader — xong khi: fresh DB có final encrypted schema, populated direct migration reject an toàn, upgrade giữ mọi giá trị/quan hệ/rules/triggers và bỏ cột plaintext; fail/cancel không mất source hoặc công bố target chưa hợp lệ, Down reject không mutate.
- [x] TSK-7 [AC-1]: Viết crypto/confidentiality/restore tests theo hành vi và fixture key riêng — xong khi: roundtrip decimal biên/culture/Unicode/null, key reopen/backup restore, missing/wrong keys, corrupt envelope và swaps bị từ chối; raw SQL/file/WAL/audit/log scans synthetic không lộ sensitive markers hoặc secret.
- [x] TSK-8 [AC-2]: Viết audit/fault/concurrency/deletion tests sync/async — xong khi: fault giữa business/audit và trước commit rollback toàn bảng; caller commit/rollback/savepoint, no-op, stale writes, cancellation, Save(false), retry/OperationId và cascade/purge được kiểm bằng fresh context, không duplicate events.
- [x] TSK-9 [AC-3]: Cập nhật regression/migration tests và thêm upgrade failure tests trên DB giả populated — xong khi: legacy seeding không dùng latest model, full field/PK/rules/trigger/FK đối chiếu qua upgrade; key/copy/readback/publish faults giữ source, target-existing reject, không skip tests hoặc sửa bốn migration cũ.
- [x] TSK-10 [AC-3]: Chạy development build, full Core/Data tests và EF model consistency — xong khi: ghi exit codes/counts thật, baseline Core 197/Data 83 behavior cùng tests mới đều qua không skip; no pending model changes, old migration hashes/HEAD/index khớp và không có user DB hay tệp ngoài scope bị đổi.
- [x] TSK-11 [AC-4]: Cập nhật ADR0015, development, Mermaid schema và PLAN 2.3/2.4 theo implementation — xong khi: mô tả đúng crypto/metadata/key restore/copy-forward/Save(false)/audit/delete/purge boundaries; 2.3 ghi mức test/review thật, 2.4 có snapshot/provenance/version/UTC/immutability/encryption/deletion nhưng chưa implement; files theo feature và mỗi primary type handwritten một file.
- [x] TSK-12 [AC-4]: Bàn giao task-only delta cho b-review độc lập và sửa finding actionable — xong khi: reviewer hiện có xác nhận kết quả sửa với evidence, docs khớp thực tế, final nêu rõ phần đã test/review và yêu cầu người dùng review bảo mật trước dữ liệu thật; không commit/stage/approve hoặc đổi cấu hình/models.
